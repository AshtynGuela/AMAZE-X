# Opening flight cutscene

Current behavior: an upward scroll, swipe, click or Enter/Space triggers a ~4.8-second automatic cutscene once models are ready. The astronaut welcome fades to a star-only backdrop; the rocket rises from below, side boosters peel away, then the shuttle detaches and keeps flying upward. The Solar System fades in behind it, with map controls appearing at the end. No continued scrolling or reverse gesture is required. Escape skips, reduced motion uses a short fade without model downloads, and the cutscene holds its end fade briefly if the map canvas is still preparing. `test-entry-flight-browser.mjs` now runs `test-entry-cutscene-browser.mjs`; newer evidence is recorded separately in `entry-cutscene-browser.json`. The earlier scroll-scrubbed results below are historical.

Current verification: production build, TypeScript and three focused staging/timing tests passed. A real-clock browser run passed automatic single-scroll completion, star backdrop, overlay removal, restored controls, click entry and reduced motion without rocket downloads; Rocky rendering was excluded. The public frontend hashes match the local build and health returns HTTP 200 for release `1872f2b`. Evidence: `entry-cutscene-browser.json` and `entry-cutscene-hosted.json` in `data/validation/`.

## Previous scrubbed implementation (superseded)

The astronaut landing screen stays intact. Scrolling up introduces the user's rocket and spacecraft, using a temporary transparent 3D canvas above the outgoing landing page and incoming Solar System. Side boosters detach first; the spacecraft leaves the upper core afterward. The core and boosters fall away, while the spacecraft recedes and fades before map controls become active. The same pose is reconstructed from scroll progress, so pausing input stops the flight and reversing input reassembles it until entry completes.

Arrow Up/Down and Page Up/Down step through the sequence. Enter/Space completes entry, and Escape skips it. The existing click-to-enter alternative is retained. Touch uses the same progress controller. Reduced motion bypasses the new 3D layer and its model requests. A failed model or WebGL context falls back to normal entry; the final reveal waits for the map canvas rather than a planet-model download.

The original files under `ROCKETS/` remain untouched. The web versions retain their meshes, textures and named nodes, cap embedded PNG textures at 1024 pixels, and use high-precision Meshopt compression. No decimation or mesh joining is applied. The combined size drops from 37,615,300 bytes to 7,943,472 bytes. Source/output SHA256 hashes are recorded in `public/assets/entry/assets.json`. The source folder is excluded from Docker context; only the prepared public assets ship.

`src/EntryFlight.tsx` clones the cached scenes, keeps exhaust with each detached booster, and samples the supplied flame tracks from scroll time. The rocket and spacecraft axes are normalized separately. Frames render only on progress, viewport or visibility changes; there is no continuous flight animation loop. The canvas, cloned materials and mixer bindings are released on entry completion or skipping. Map controls stay inert while the welcome dialog is active. Asset preparation and map startup are ordered to avoid competing at the first scroll.

Reproduce assets with `npm run assets:entry` (requires the source folder and the pinned glTF Transform CLI). Run `node --test tests/entry-flight.test.mjs` for stage order/reversal/no-snap behavior, and `npm run test:entry-flight-browser` against a running server (`BASE_URL` sets the origin). Use a production build for the integration check: Vite's first-time dependency optimization can reload the introduction while a development browser test is running.
